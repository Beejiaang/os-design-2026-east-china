# 项目统一口径与协作约定

版本：2026-11-16 / 协作约定 1。根目录 `AGENTS.md` 是 Agent 入口。此约定统一工程表述，不替代用户指令或赛事正式规则。

## 权威信息分别在哪里

| 问题 | 以什么为准 |
|---|---|
| 项目目标、术语、范围 | 本文件 |
| 角色、阶段与截止安排 | work-allocation.md；旧 project-plan.md 仅作历史 |
| 实际运行输入输出、单位、版本、状态 | data-contract.md、schemas/ 与实际实现；发现不一致必须修正并补测试 |
| 当前做到了什么、下一步接什么 | agent-handoff.md 与对应提交/验收记录 |
| 实测结果 | 对应提交的原始结果和日志；文档不能覆盖失败证据 |
| 赛事要求与正式提交 | 官方最新规则、submission-checklist.md 及真实接收状态 |

README 是入口，不是独立维护另一份协议。历史证据不重写成当前版本；新实现不得用旧测试日志冒充已验证。遇到冲突时定位拥有该概念的文件、检查代码与证据，明确修改依据；不能通过删除限制来“统一”。

## 对外描述

统一名称/范围：**面向 openEuler 数据处理任务的 CPU 资源约束与性能回归分析工具**。当前没有另行确认的产品名。

项目用途：在固定 Linux 环境中控制单进程数据任务的 CPU 时间上限，重复执行、保存可追溯原始数据；在功能一致、输入和资源/环境兼容的前提下展示配置差异及历史性能变化，保留失败和无法判断的原因。

禁止将以下内容说成已完成：通用根因诊断、自动调优、覆盖所有资源类型、统计回归准确率、生产可靠性或真实业务性能提升。统计与报告在 C 交付且验收后才能更新完成口径。

“方向 A”指选题，“成员 A/B/C”指职责；成员 A 不默认等于队长。角色代号不代表真实姓名、账号、人工贡献比例或已经投入的时长。

## 模块归属和调用关系

| 角色 | 主维护路径 | 应交付给下一环节 | 不应在本角色中替代的工作 |
|---|---|---|---|
| A 系统与集成 | src/runner、src/collector、公共 schemas、执行/复验脚本 | 执行接口、环境与配额证据、最终记录、异常和清理机制 | 不用退出码/输出哈希宣称算法正确，不替 C 作统计结论 |
| B 负载与实验 | workloads、experiments、负载/实验专属 tests、实验说明 | 固定种子输入、规模/校验值、代码版本、可调用 argv、独立正确性校验、异常样本 | 不自行改 runner 状态/计时单位或将故障夹具当真实性能数据 |
| C 分析与报告 | src/analysis、src/report、分析/报告专属 tests、demo | 数据校验、样本筛选、分布与差异、离线报告、无法比较原因 | 不重新执行负载、静默修正原始结果或从变化直接推断根因 |

公共 README、协议、schemas 和跨角色测试是共享文件：变更方在 PR 写清受影响角色、兼容性和迁移步骤。跨模块修复允许，但不得删除他人的未完成标记或声明人工作业已完成。

B 通过配置中的 argv 接入 runner；当前示例 cpu_probe 是 A 的集成探针。B 应实现真正的分组聚合与独立参考结果；不能把改名后的探针称为已完成数据任务。C 读取最终记录，先做结构校验和兼容前提检查，再做分析。A 在 C 交付后核对报告数字与 run_id 原始记录。

## 指标与结论分层

| 术语 | 严格含义 |
|---|---|
| 执行成功 | 最终 status=success，退出 0，配额及清理证据完整；尚不能证明算法正确 |
| 功能正确 | B 的独立校验对输入和输出通过；stdout 哈希相同只是一项辅助证据 |
| 配额生效 | 服务内实际控制信息与请求相符；不要求耗时成固定倍数 |
| 配置对照 | 同一任务/输入对不同配额的描述性对比，不是历史退化判定 |
| 历史比较 | 输入、资源、环境、执行器和输出兼容，比较对象允许是不同负载版本 |
| 性能变化 | 有数据支持的变化比例/分布，尚未说明统计显著或根因 |
| 性能退化判定 | C 的明确规则、验收样本与误报/不确定情况都已记录后才可使用 |
| 根因确认 | 另有验证实验；单次波动、节流次数或日志片段都不够 |

100% 表示一个逻辑 CPU 的时间上限；不能按整台机器 100% 理解。null 表示本工具未主动施加本地配额；祖先/宿主机可能仍有限制。wall_seconds、cpu_seconds、cgroup CPU 统计的测量范围不同，不能混用；单位见数据协议。

## 完成状态统一用语

| 用语 | 允许的证据 |
|---|---|
| 计划/待实现 | 没有可运行实现或尚未实际执行 |
| 已实现、待验证 | 有代码，还没有匹配该代码版本的验证 |
| 代理实测通过 | 代理在明确环境和提交上实际运行，有日志/原始数据 |
| 干净源码复验通过 | 独立检出干净提交复验；同一代理/机器仍不能称队友复现 |
| 交叉验收通过 | 非实现者实际复现并留下其操作与问题记录 |
| 阶段通过 | 阶段涉及的 A/B/C 项和人员/平台条件均有证据 |
| 已推送/已建 PR/已合并 | 分别给出远端分支/PR/合并提交证据 |
| 已正式提交 | 官方平台接收状态、版本、时间和提交人均可追溯 |

自动测试、代码生成或 AI 自审不能冒充队友的人工作业。用户仅授权开发时，不延伸为代办报名、发送队友消息或提交比赛。

## 基线和实验规则

- 固定目标环境；跨机器流程复现不直接合并性能基线。为基线保留干净提交、输入标识、固定输出/独立正确性证据、配额、父级限制和执行器版本。
- `workload_version` 应可追溯到固定实现，优先使用干净 Git 提交或源文件校验值；`input_id` 应能追溯种子、规模和输入内容校验，不能只写“默认输入”。
- 记录预热、重复次数、执行顺序、超时和已知宿主机干扰。少量样本仅用于验证流程，不能宣称显著性。
- 阈值设计与验收样本尽量分开，保留同条件样本、已知变慢样本及误报/不确定情况。不得先看验收结果再调阈值却仍称独立验收。
- 原始数据只追加保存，不为让报告好看而修改。修订计算方法产生新派生结果，标明输入原始文件和算法版本。

## Git 和 Agent 交接

开始前获取当前分支、commit 和工作树状态；重要实现通过角色分支和 PR 交付。只正常推送，不强推共享分支；未经明确授权不合并 PR。依赖未合入 main 的实现时，写明来源分支/commit，不能让下一个 Agent 默认从旧 main 开始。

优先让每个角色在独立工作目录/分支工作，避免多个 Agent 同时改共享文件。接口变更先准备具体兼容方案和验证；更新 schema、协议和受影响调用方说明。协作记录不替代实际代码审查。

每次结束更新 handoff 的角色条目，并按模板列提交、路径、命令、证据、限制和下一步。保留失败和修复说明，不保存无关私人聊天、私钥或令牌。原始赛事 PDF、虚拟机镜像、模型文件不进入代码库。
