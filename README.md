# 2026 操作系统设计赛 · 华东区域赛

2026 年操作系统设计赛华东区域赛参赛项目仓库，涵盖选题分析、技术方案、源代码、测试实验、开发文档与演示材料。

三人团队已选择 **OS 应用开发赛道（赛道 2）的方向 A**，范围收窄为 **面向 openEuler 的 CPU 配额行为验证与性能回归测试工具**。当前处于学习与原型准备阶段，后续开发内容持续在本仓库维护。

## 从这里开始

1. 阅读 **[成员分工、学习内容与截止计划](docs/project-plan.md)**：队长约 50%、两名队员各约 25%，从基础学习排到正式提交。
2. 按计划提交环境记录、原型、测试与报告；具体姓名及可投入时间由队内补充。
3. 在 [讨论 Issue](https://github.com/Beejiaang/os-design-2026-east-china/issues/1) 保留判断依据和待解决问题，按 [协作说明](CONTRIBUTING.md) 提交修改。
4. 历史资料：[八类选题分析](docs/topic-analysis.md)、[队员评价与决策记录模板](docs/team-review.md)。此前的 EulerLens 是方向 B 候选，不是本项目的当前方案。

**当前计划：**11 月 8 日可演示初稿，11 月 29 日冻结功能，12 月 20 日内部提交截止。按已发章程的 12 月 24 日作品截止倒排；平台日期字段差异的核实任务见计划文档。

## 仓库定位

- 本 GitHub 仓库是团队持续协作的主仓库，用于分享、讨论，以及后续源代码、测试、开发文档与演示材料的版本管理。
- 赛事正式提交与开发过程留痕按组委会 GitLab 要求执行；选题后尽早建立比赛仓库并同步，不能以本 GitHub 仓库代替正式提交。
- 当前只有方案和模板，**没有已验证的原型、性能提升或诊断准确率**。
- 本仓库不存放报名证件、个人联系方式、令牌、虚拟机镜像或用户提供的原始赛事 PDF。
