## 1. 首版做什么

固定一个 openEuler 版本和一种虚拟机架构。先用可校验计算负载验证配额，再接入一个结果可校验的分组聚合任务；数据可按固定种子生成。不在首版建设完整数据库或分布式平台。

| 模块 | 首版要求 | 验收证据 |
|---|---|---|
| 环境检查 | 记录系统、内核、CPU、Python、任务版本与可见父级限制；检查权限和资源控制能力 | 环境记录与不适用提示 |
| 执行与采集 | 三档 CPU 配额，自动重复；记录耗时、CPU 时间、资源组统计差值、退出状态；超时和失败后清理 | 真实 JSON/CSV、失败日志、清理检查 |
| 数据处理负载 | 固定输入、固定实现的分组聚合；能校验输出；先单进程 | 生成脚本、输入参数、正确性校验 |
| 行为实验 | 同一任务和输入下比较不同配额 | 配置、原始结果、报告与机制解释 |
| 历史回归 | 同输入、同资源条件和兼容环境下比较基线与当前任务版本；功能输出保持一致 | 基线元数据、比较结果与不确定原因 |
| 报告 | 显示分布、变化比例、失败与缺失指标、比较前提和局限 | 离线 HTML、原始结果入口 |
| 独立复现 | 非实现者按 README 安装并完成演示 | 复现记录、实际问题和修复 |

CPU 配额是上限，不能承诺耗时精确翻倍。“本次未主动限制”不等于没有父级约束。跨机器复现用于验证流程，不能直接混入同一性能基线。检测到性能变化不等于确认根因。

首版暂不包含：自动调优、完整根因诊断、多进程分析、内存/磁盘/网络全覆盖、账户系统和复杂网页。并行度实验放在核心验收通过后评估。

## 4. 接口与实验约定

本轮补充进展（2026-11-17）：在本地 `feat/b-comparison-validation` 完成原生命令正常场景对照 36 次、固定 100% 配额的健康/额外 5%、15%、25% 规则实验 48 次，72 条非预热测量通过独立校验；最终 29 项目标机测试通过。追加范围敏感性描述但未改原规则阈值，细化现有计时点文档。见 [扩展验证](../validation/comparison-validation.md)。不等同非实现者复验、全部框架对比或整阶段通过。

- 每次实验至少记录：schema_version、run_id、数据来源、系统环境、代码版本、输入种子/规模/校验标记、配额与可见父级限制、各项指标及单位、退出码、状态、错误原因。
- 原始结果与汇总分开保存；缺失指标用 null 并解释，不能填 0。报告按运行编号追溯原始数据。
- C 可先使用标明 synthetic 的样例；正式结论仅使用真实采集数据。代码版本是比较对象时，要固定其他条件并校验输出一致。
- 先小规模试跑估计波动，再确定重复次数与判定规则；记录预热、实验顺序和宿主机干扰。不凭固定少量重复宣称统计显著。
- 阈值设定和验收样本尽量分开；既测已知变慢样本，也测同条件重复样本，记录误报及不确定情况。
- 对权限不足、超时、任务报错、指标缺失、清理失败、基线不兼容均保留明确状态。
- 同类比较使用相同场景，披露已有组件与本队增量；不能将设置配额、画图或调用 AI 单独当作创新。
