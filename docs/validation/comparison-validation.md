本队与 GNU time + systemd-run 组合每档各一次预热、五次测量；预热先行，随后方法/配额按固定种子混排，串行执行。36 次均成功，输出逐份与 SQLite 参考一致，实际配额通过核验；可见父级限制一致，清理核验全部通过。输入与负载文件运行前后哈希一致。**30 个非预热样本用于描述性对照，6 个预热排除**。

GNU time 1.10 在普通用户目录编译，无全局安装；保留构建日志、工具版本、可执行文件 SHA256、源码下载 SHA256 与每次原生 argv/标准输出/时间原文/服务内快照/清理结果。本队为 GNU 命令补充的验证脚本没有算成 GNU 原生功能。量化中位数表及不同计时范围见同类工具说明，不输出速度排名。

### 规则扩展：48 次

六个场景在开始前写入 plan.json：基线、正常复测 1、额外处理前 5% 输入、额外处理前 15%、额外处理前 25%、正常复测 2。每场景一次预热、七次测量；阈值仍为先前固定的 15%，每侧最少五条。没有看结果再调阈值。场景顺序固定，前后两组正常复测观察漂移；未随机交错场景，不能据此排除时间顺序混杂。

额外处理使用同一个聚合函数处理输入前缀，仅最后的额外结果被丢弃，最终 stdout 仍是完整输入的正确聚合。源码哈希和 extra 参数组成版本标识；工作量百分比是受控参数，不保证相同百分比的 wall 增长。它不是实际线上退化事故。

### 负向前提与异常处理

对真实摘要的明确标识副本构造五类：只保留四条样本、基线与当前 run_id 重叠、complete=false、input_id 改变、environment 改变，均返回 unable_to_compare。派生拒绝场景不增加“真实测量数”，没有改写 result.json。

对 GNU time 的空文件/非有限值/缺列/负指标，及缺少实际 cpu.max、父级控制器证据的情况增加拒绝测试；没有用默认零掩盖缺失。原生工具正常场景全部通过，不代表已完成它们的失败/超时/权限场景横向验收。
