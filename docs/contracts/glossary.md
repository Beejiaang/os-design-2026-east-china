# 统一术语表

字段、单位与版本以[数据协议](data-contract.md)及schema为准，完成状态以[项目统一口径](../project/project-contract.md#完成状态统一用语)为准。本表集中解释，不能替代原始证据。

| 术语 | 含义和边界 |
|---|---|
| quota_percent | 一个逻辑CPU的时间上限百分比；100%不是整机CPU利用率，50%不承诺wall精确翻倍 |
| null配额 | 本工具未主动设置叶节点配额；可见祖先与不可见宿主机约束仍可能存在 |
| wall_seconds | worker中单调时钟区间，包含服务内快照/文件打开/进程启动/等待及采样开销，见协议精确计时点 |
| cpu_seconds | 已回收子进程user+system秒；不含worker本身，超时未回收后代可能不全 |
| cpu_stat_delta | cgroup两次采样的内核计数差，包含worker区间开销；*_usec为微秒，nr_*为次数，不等于cpu_seconds |
| 配置对照 | 固定任务和输入比较不同配额的描述性结果 |
| 历史比较 | 固定同档资源、输入、输出及环境/代码兼容条件，比较不同负载版本 |
| slowdown_needs_review | 超过探索性中位数阈值，提示复核；不是统计显著或根因确认 |
| no_threshold_signal | 没有触发既定阈值；不能写成无退化 |
| unable_to_compare | 比较证据不足或不兼容，保留拒绝理由 |
| threshold_sensitive | 已观察范围能组合出阈值两侧比值；不是置信区间 |

完成状态原表实际列出八种，不为凑“六档”而删项：计划/待实现、已实现待验证、代理实测通过、干净源码复验通过、交叉验收通过、阶段通过、已推送/已建PR/已合并、已正式提交。后三种Git动作仍分别报告；代理检查不认领人员完成或赛事接收。
